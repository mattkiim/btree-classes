## From a bandit to a world with state

In last week's bandit, an action did not change the situation. In Gridworld,
moving changes what can happen next. A **Markov Decision Process (MDP)** consists
of:

- **states** $S$: descriptions of the current situation;
- **actions** $A$: choices available to the agent;
- **transition rule** $P$: how state and action determine the next state;
- **reward rule** $R$: immediate feedback from a transition;
- a **discount factor** $\gamma$, which will matter when valuing future rewards.

Our state is a `(row, column)` tuple. The four actions are strings. A wall is not
a state the agent can occupy. The goal and pit are **terminal states**: the
episode ends when either is entered.

## The Markov property

A state is Markov when it contains enough information to predict the next-state
and reward distribution given the next action. Informally:

> Given the present state and action, the past adds no needed information about
> what happens next.

For a fully observed static maze, `(row, column)` is enough. If a locked door
stays open after collecting a key, location alone is not enough; the state must
also record whether the key was collected.

## Gridworld rules

We will use a 5×5 board:

```text
S . . # .
. # . # .
. # . . .
. . # # .
. . . P G
```

- `S` starts at `(0, 0)`, `G` is the goal, and `P` is the pit.
- An ordinary move costs `-1`.
- Entering the goal gives `+10`; entering the pit gives `-10`.
- Moving off the board or into a wall leaves the agent in place and still costs
  `-1`.
- Calling `step` after termination is an error; call `reset` first.

The step cost makes shorter successful paths preferable, even before we learn
formal value functions.

## Live coding: transitions without side effects

First write a pure model function. It answers “what would happen?” without
moving the live agent.

```python
ACTIONS = {
    "UP": (-1, 0),
    "DOWN": (1, 0),
    "LEFT": (0, -1),
    "RIGHT": (0, 1),
}

def transition(state, action, rows, cols, walls, goal, pit):
    if action not in ACTIONS:
        raise ValueError("unknown action")
    dr, dc = ACTIONS[action]
    candidate = (state[0] + dr, state[1] + dc)
    blocked = not (0 <= candidate[0] < rows and 0 <= candidate[1] < cols)
    if blocked or candidate in walls:
        candidate = state
    reward = 10 if candidate == goal else -10 if candidate == pit else -1
    done = candidate in (goal, pit)
    return candidate, reward, done
```

## Live coding: an environment with state

```python
class Gridworld:
    def __init__(self):
        self.rows, self.cols = 5, 5
        self.start, self.goal, self.pit = (0, 0), (4, 4), (4, 3)
        self.walls = {(0, 3), (1, 1), (1, 3), (2, 1), (3, 2), (3, 3)}
        self.reset()

    def reset(self):
        self.state = self.start
        self.done = False
        return self.state

    def model(self, state, action):
        return transition(state, action, self.rows, self.cols,
                          self.walls, self.goal, self.pit)

    def step(self, action):
        if self.done:
            raise RuntimeError("episode is over; call reset")
        self.state, reward, self.done = self.model(self.state, action)
        return self.state, reward, self.done
```

Separating `model` from `step` matters. Later algorithms can ask about possible
transitions without changing the current episode.

## Policies and rollouts

A **policy** tells the agent which action to select in each state. It can be a
dictionary for now. A **rollout** (or episode) is one sequence generated by
following a policy.

```python
def rollout(env, policy, max_steps=50):
    state = env.reset()
    trajectory = []
    for _ in range(max_steps):
        action = policy.get(state, "RIGHT")
        next_state, reward, done = env.step(action)
        trajectory.append((state, action, reward, next_state))
        state = next_state
        if done:
            break
    return trajectory
```

The maximum prevents a bad policy from looping forever. It is an experiment
safety limit, not a terminal state in the MDP.

## Inspecting all transitions

For every non-wall, non-terminal state, print the result of all four actions.
This transition table is a powerful debugging tool: corners test boundaries,
states beside walls test collision rules, and states beside goal and pit test
terminal rewards.

```python
for row in range(env.rows):
    for col in range(env.cols):
        state = (row, col)
        if state in env.walls or state in (env.goal, env.pit):
            continue
        print(state, {a: env.model(state, a) for a in ACTIONS})
```

## Common misconceptions to watch for

- “State means the entire history.” A good Markov state retains what matters,
  not necessarily every past observation.
- “A blocked move means no transition happened.” The next state equals the old
  state, but time passes and the step reward is received.
- “Reward describes how good a state is forever.” Reward is immediate feedback;
  long-term desirability will be represented by value.
- “The policy is part of the MDP.” The MDP defines the problem; a policy is one
  way an agent behaves in it.
- “Terminal and wall mean the same thing.” Walls cannot be occupied; terminal
  states are entered and then end the episode.
